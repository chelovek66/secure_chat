## 1. Объект тестирования

Объектом комплексного тестирования является программный комплекс **Secure Chat**, включающий клиентскую часть (PyQt5 GUI, криптографическая подсистема, модуль безопасного обновления, менеджер конфигураций) и серверную часть (FastAPI REST API, маршрутизатор аутентификации, SQLite хранилище учетных записей и аудит-логов).

### 1.1 Тестируемые компоненты и модули:
1. **Подсистема аутентификации и разграничения доступа**:
   - `server.auth_router`: эндпоинты `/register`, `/login`, `/logout`, `/me`.
   - `server.database`: персистентное хранилище абонентов, счетчик неудачных попыток `failed_attempts`, блокировка учетной записи (`status = 'locked'`).
   - `client.gui.auth_dialog`: клиентский диалог аутентификации с аппаратным подсчетом попыток, блокировкой полей ввода пароля и кнопки входа при достижении 5 неудачных попыток.
2. **Подсистема безопасного обновления и защиты от подмены файлов**:
   - `common.update_crypto`: канонизация манифестов, валидация SBOM CycloneDX 1.5, подпись и верификация Ed25519.
   - `client.updater`: проверка цифровой подписи релиза, проверка поэлементных контрольных сумм каждого распакованного файла по манифесту (`software_manifest.json`), автоматический откат (rollback) при несовпадении или внедрении посторонних файлов.
   - `server.update_router`: проверка JWT-токенов устройств, раздача манифестов и одноразовых токенов скачивания.
3. **Криптографическая подсистема E2EE**:
   - `client.crypto.bee2_wrapper`: базовые криптографические примитивы (симметричное шифрование, дайджесты, контейнеры).
   - `client.crypto.bign`: генерация ключевых пар, выработка и верификация ЭЦП.
   - `client.crypto.belt`: аутентифицированное шифрование с контролем целостности (MAC).
   - `client.crypto.hybrid`: гибридный протокол шифрования полезной нагрузки сообщений.
   - `client.crypto.keystore`: парольная защита ключевых контейнеров на диске.
4. **Подсистема контроля целостности**:
   - `common.integrity.SoftwareIntegrityManager`: пофайловое хэширование файлов и проверка цифровой подписи манифеста целостности.

## 2. Методика и тестовое окружение

### 2.1 Программное окружение:
- **Операционная система:** Windows 10/11 x64
- **Среда исполнения:** Python 3.12.0 x64
- **Фреймворки тестирования:**
  - `pytest` 9.1.1 — тест-раннер и ассерты;
  - `pytest-cov` 7.1.0 — замер покрытия строк кода (coverage);
  - `hypothesis` 6.170.15 — property-based тестирование и генеративный фаззинг;
  - `FastAPI TestClient` (Starlette / HTTPX) — тестирование REST API эндпоинтов.

### 2.2 Применяемые виды тестирования:
- **Функциональное позитивное тестирование (Positive Functional Testing):** проверка штатных сценариев работы при корректных входных данных.
- **Функциональное негативное тестирование (Negative Functional Testing):** проверка устойчивости к неверным учетным данным, некорректным отпечаткам устройств, поддельным цифровым подписям и поврежденным шифротекстам.
- **Тестирование граничных значений (Boundary Value Analysis):** проверка предельных длин логинов (2..64 символа), паролей (1..128 символов), размеров сообщений (0 байт, 1 байт, 64 КБ), конфигурационных таймаутов (0.2..60с, 1.0..120с).
- **Стресс- и фаззинг-тестирование (Fuzzing):** генерация псевдослучайных и мутированных бинарных векторов с проверкой на необработанные падения (Unhandled Crashes) при длительности работы **не менее 60 секунд**.

### 3.4 Фаззинг-тестирование (`fuzz/fuzz_parser.py` и `test_fuzzing.py`)

Фаззер непрерывно выполнялся в течение **60 секунд** с генерацией случайных бинарных последовательностей, мутацией байтов и внедрением экстремальных значений (NULL-байты, переполнения, инъекции спецсимволов).

#### Результаты фаззинг-кампании:
- **Время непрерывной работы:** `60.00` секунд
- **Всего проверено входных векторов:** `2,332,712`
- **Средняя производительность:** `38,878.0` входов/сек
- **Количество обнаруженных падений (Unhandled Crashes):** `0`
- **Количество зафиксированных исключений в crash-репродьюсере:** `0`

#### Распределение нагрузки по целям фаззинга:
1. `SBOM CycloneDX Parser`: **466,534** итераций (отказы обрабатываются штатно через исключения `ValueError`, `KeyError`);
2. `Manifest Canonicalizer`: **467,350** итераций (строгая обработка JSON и UTF-8);
3. `Crypto Payload Decoder`: **465,602** итераций (имитозащита и десериализация устойчивы к искажениям байтов);
4. `BKey Container Unwrapper`: **465,441** итераций (безопасное отклонение битых ключевых контейнеров);
5. `Pydantic Request Models`: **467,785** итераций (входная санитизация сетевых запросов).

Дополнительно в тестовом пакете запущены Hypothesis-тесты (`test_fuzzing.py`), подтвердившие свойство инвариантности: **ни один сгенерированный входной вектор не приводит к неконтролируемому аварийному завершению процесса**.

## 4. Найденные дефекты и реализованные доработки безопасности

В процессе тестирования и анализа защищенности приложения были выявлены и устранены следующие потенциальные дефекты:

| № | Выявленная проблема | Уровень критичности | Реализованное исправление | Подтверждение устранения |
|---|---|:---:|---|---|
| 1 | **Уязвимость подмены файлов обновления (Tampering / Substitution Attack)** | **Критический (High)** | В модуль `Updater` внедрен двухуровневый контроль ЭЦП: 1) проверка цифровой подписи манифеста выпуска Ed25519; 2) проверка пофайловых хэшей каждого извлеченного файла по эталонному `software_manifest.json`. При малейшей модификации или внедрении посторонних файлов выполняется автоматический откат к рабочей резервной копии. | Тесты `test_tampered_update_manifest_rejected`, `test_tampered_update_package_rejected` — **PASSED** |
| 2 | **Уязвимость к подбору паролей методом полного перебора (Brute-Force)** | **Высокий (High)** | Добавлен счетчик неудачных попыток `failed_attempts` в SQLite-таблицу пользователей. При 5 неверных попытках статус пользователя переходит в `locked`, генерируется событие аудита безопасности `ACCOUNT_LOCKED`, а сервер возвращает HTTP 423. На стороне клиента диалог блокирует поле ввода пароля и кнопку входа. | Тест `test_login_lockout_after_5_failed_attempts` — **PASSED** |
| 3 | **Отображение названий криптографических стандартов и алгоритмов в интерфейсе** | **Низкий (UI/UX)** | Проведена полная очистка пользовательского интерфейса (окно «О программе», диалог контроля целостности, журналы аудита, таблицы БД) от упоминания конкретных алгоритмов. | Визуальный и кодовый аудит — наименования приведены к нейтральным терминам («Основной криптографический модуль», «Контроль целостности ПО»). |
| 4 | **Отсутствие валидации экстремальных длин полей ввода** | **Средний (Medium)** | Модели Pydantic `UserRegisterRequest` и `UserLoginRequest` усилены граничными проверками `min_length` и `max_length`. В диалог авторизации добавлен индикатор надежности пароля с проверкой порога в 8 символов. | Набор тестов `test_boundary_values.py` — **PASSED** (100%) |
