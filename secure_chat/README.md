# Secure Chat — Программный комплекс защищенного обмена сообщениями

Программный комплекс **«Secure Chat»** — это готовое к промышленной эксплуатации (Production-Ready) клиент-серверное приложение для сквозного шифрованного обмена сообщениями (End-to-End Encryption, E2EE), спроектированное в строгом соответствии с государственными стандартами Республики Беларусь в области криптографической защиты информации.

---

## 1. Соответствие стандартам Республики Беларусь

Приложение опирается на национальную криптографическую библиотеку **Bee2 (НИИ ППМИ БГУ)** и реализует следующие стандарты:

| Стандарт | Алгоритм / Механизм | Применение в Secure Chat |
| :--- | :--- | :--- |
| **СТБ 34.101.31-2011** | `belt` (режим `belt-che`) | Симметричное шифрование сообщений (256-битный сессионный ключ), 128-битная синхропосылка (IV), 128-битная имитовставка (MAC). Гарантирует конфиденциальность и целостность сообщений. |
| **СТБ 34.101.45-2013** | `bign` (`bign-curve256v1`) | Асимметричная криптография: формирование и верификация ЭЦП сообщений (`bign-sign`), транспортирование сессионных ключей получателям (`bign-keytrans`). |
| **СТБ 34.101.47-2017** | `bash` (хеш-функция) | Хеширование данных, выработка ключей KDF и контроль целостности. |
| **СТБ 34.101.78-2017** | `bkey` / `belt-kwp` | Защита личных закрытых ключей пользователей в локальном контейнере с парольной аутентификацией. |

> **Нативный модуль Bee2 и Fallback Engine:**
> При наличии скомпилированной динамической библиотеки `bee2.dll` (Windows) или `libbee2.so` (Linux) приложение автоматически вызывает C-API НИИ ППМИ БГУ через `ctypes`. При её отсутствии прозрачно активируется автономный Fallback-модуль, предоставляющий идентичный интерфейс, тестовые векторы и поведение.

## 3. Быстрый запуск

### 3.1. Установка зависимостей

Убедитесь, что у вас установлен Python 3.11+:

```bash
git clone <url_to_repo> secure_chat
cd secure_chat
pip install -r requirements.txt
```

### 3.2. Запуск сервера

#### Вариант А: Локальный запуск через Python

```bash
uvicorn server.app:app --host 0.0.0.0 --port 8000 --reload
```

Сервер будет доступен по адресу: `http://localhost:8000`.
Интерактивная документация OpenAPI (Swagger): `http://localhost:8000/docs`.

#### Вариант Б: Запуск в Docker / Docker-Compose

```bash
cd docker
docker-compose up -d --build
```

Сервер запускается под непривилегированным пользователем `appuser` с настроенным Healthcheck.

---

### 3.3. Запуск клиентского приложения (PyQt5)

В отдельном окне терминала запустите:

```bash
python client/main.py
```

#### Порядок работы в GUI:
1. **Генерация или импорт ключей:**
   * Откройте меню «Ключи СТБ» -> «Управление ключами».
   * Нажмите «Сгенерировать новую пару (СТБ 34.101.45)».
   * При желании введите пароль для защиты контейнера по стандарту СТБ 34.101.78 (`belt-kwp`) и сохраните файл ключа (`.json`).
2. **Регистрация на сервере:**
   * В главном окне укажите адрес сервера (по умолчанию `http://localhost:8000`), ваше имя пользователя и нажмите «Подключиться к серверу».
   * Ваш открытый ключ будет автоматически передан и зарегистрирован на сервере.
3. **Обмен зашифрованными сообщениями:**
   * Нажмите «Пользователи», выберите собеседника и откройте «Чат».
   * Сообщения автоматически:
     1. Подписываются вашей ЭЦП (`bign-sign`).
     2. Шифруются одноразовым 256-битным сессионным ключом (`belt-che`).
     3. Сессионный ключ транспортируется открытым ключом получателя (`bign-keytrans`).
     4. Сервер передает только непрозрачный криптоконтейнер и не имеет доступа к открытому тексту (Zero-Knowledge / E2EE).

## 4. Сборка Standalone Windows EXE (PyInstaller)

Для создания полностью автономного исполняемого файла клиента выполните:

```bash
pyinstaller --noconfirm --onedir --windowed --name "SecureChat" `
    --add-data "client/crypto;client/crypto" `
    client/main.py
```

Готовый дистрибутив будет создан в каталоге `dist/SecureChat/`.

## 7. Безопасность и соответствие критериям Production Readiness

1. **Защита в памяти и протоколах:** Личные ключи и открытый текст сообщений не сохраняются в логах.
2. **Целостность и аутентичность:** Каждое сообщение защищено 128-битным имитокодом `belt-che` и 64-байтной ЭЦП `bign-sign`. Модификация даже одного бита шифртекста или пакета немедленно бракуется получателем.
3. **Защита от XSS и инъекций:** Тексты входящих и исходящих сообщений в интерфейсе Qt экранируются через `html.escape()`.
4. **Неблокирующий UI:** Сетевой опрос и ресурсоемкая криптография вынесены в изолированные потоки `QThread`.
5. **Деструктивная доставка:** Сообщения удаляются из серверной очереди сразу после получения адресатом (POP semantics), что минимизирует риски компрометации данных на сервере.
