# sastsca — Консольный SAST/SCA анализатор безопасности

Модульный статический анализатор безопасности исходного кода (**SAST**) и состава сторонних зависимостей (**SCA**). Разработан в рамках практической работы «Разработка SAST/SCA-анализатора».

---

## 1. Архитектура и компоненты

Инструмент построен по классическому многослойному конвейеру анализа:
```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  Сбор файлов │ ──> │  Парсинг /   │ ──> │  Движок      │ ──> │    Отчет     │
│   (Walker)   │     │ Нормализация │     │    Правил    │     │  (Reporter)  │
└──────────────┘     └──────────────┘     └──────────────┘     └──────────────┘
```

1. **File Walker (`sastsca/walker.py`)**: рекурсивный обход каталога проекта с автоматическим считыванием правил `.gitignore`, исключением бинарных файлов, виртуальных окружений (`venv/`), сборочных каталогов (`dist/`, `build/`) и системных директорий.
2. **SAST Rule Engine (`sastsca/rules/`)**: набор независимых правил лексического и синтаксического анализа (AST).
3. **SCA Resolver & Matcher (`sastsca/parsers/`, `sastsca/sca.py`)**: извлечение прямых зависимостей из манифестов (`requirements.txt`, `package.json`) и сопоставление с открытой базой уязвимостей **OSV (Open Source Vulnerabilities)** через REST API `https://api.osv.dev/v1/query` со встроенным автономным офлайн-кэшем.
4. **Reporters (`sastsca/reporters/`)**: структурированный вывод результатов в форматы **JSON**, **Markdown** и интерактивный терминальный вывод.
5. **Config (`.sastsca.yml`)**: управление порогами блокировки (`fail_on`), включением/выключением отдельных правил и шаблонами исключений.

## 2. Каталог правил анализа безопасности (SAST)

| ID правила | Наименование | Метод анализа | Критичность | CWE | Описание |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **SAST-001** | `Hardcoded Secret` | Regex (Лексический) | High / Critical | CWE-798, CWE-312 | Поиск захардкоженных паролей, API-ключей, токенов и закрытых ключей RSA/PEM. Фильтрует типовые плейсхолдеры (`changeme`, `admin`) и чтение из `os.getenv`. |
| **SAST-002** | `Unsafe Function Call` | **AST (Синтаксический)** / Regex | High | CWE-95, CWE-78 | Обнаружение опасных вызовов `eval()`, `exec()`, `os.system()`, `os.popen()`, `subprocess.*(..., shell=True)` и JS `eval()`. |
| **SAST-003** | `SQL Injection` | **AST (Синтаксический)** | High | CWE-89 | Обнаружение интерполяции f-строк, оператора `%`, метода `.format()` и конкатенации `+` внутри вызовов `cursor.execute(...)`. |
| **SAST-004** | `Insecure Deserialization`| **AST (Синтаксический)** | Critical | CWE-502 | Выявление небезопасной десериализации `pickle.loads/load`, `yaml.load` без `SafeLoader`, а также `marshal.loads`. |
| **SAST-005** | `Weak Cryptographic Primitive` | **AST (Синтаксический)** / Regex | Medium | CWE-328, CWE-327 | Обнаружение устаревших и подверженных коллизиям хэш-функций `hashlib.md5()`, `hashlib.sha1()` и слабых шифров. |

## 3. Модуль анализа состава ПО (SCA)

- **Поддерживаемые манифесты**:
  - `requirements.txt` (Python / PyPI)
  - `package.json` (Node.js / npm)
- **Сверка с базами уязвимостей**:
  - **Онлайн**: запрос к REST API базы **Google OSV** (`https://api.osv.dev/v1/query`).
  - **Офлайн**: локальный кэш типовых уязвимостей для надежной работы без доступа к сети.
- **Выходные параметры**: имя пакета, установленная версия, идентификатор CVE / GHSA / OSV, уровень критичности CVSS, рекомендация безопасной версии для обновления.

## 4. Способы подавления ложных срабатываний (False Positives)

Для подавления срабатываний на проверенных участках кода поддерживаются специальные комментарии:
- В Python: `# nosec`, `# sast-ignore`, `# noqa`
- В JavaScript: `// sast-ignore`, `/* sast-ignore */`

Пример:
```python
# Безопасный вызов с фиксированной строкой в тестовом стенде:
eval("1 + 1")  # nosec
```

## 5. Установка и запуск

### Запуск через Python:
```powershell
# Запуск сканирования проекта с текстовым выводом в терминал
py -3.12 -m sastsca scan --path "D:\secure_chat"

# Генерация отчета в формате JSON
py -3.12 -m sastsca scan --path "D:\secure_chat" --format json --output report.json

# Генерация отчета в формате Markdown
py -3.12 -m sastsca scan --path "D:\secure_chat" --format md --output report.md

# Запуск с порогом блокировки (завершится с кодом 1 при наличии находок уровня HIGH и выше)
py -3.12 -m sastsca scan --path "D:\secure_chat" --fail-on high
```

### Коды возврата CLI (Exit Codes):
- `0`: Находок выше заданного порога критичности не обнаружено.
- `1`: Обнаружены уязвимости с уровнем критичности равным или выше `--fail-on` (сигнал для сбоя CI/CD pipeline).
- `2`: Ошибка выполнения (неверно указан путь, поврежден синтаксис конфига).

## 6. Запуск тестов анализатора

```powershell
py -3.12 -m pytest tests/ -v
```
Все 9 юнит-тестов проверяют точность каждого правила, отсутствие ложных срабатываний и коды возврата CLI.
