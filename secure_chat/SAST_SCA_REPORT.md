# Пояснительная записка к практической работе
## «Разработка SAST/SCA-анализатора безопасности собственного проекта»

### 1. Объект и цель разработки
- **Объект анализа**: собственный проект — клиент-серверный защищенный мессенджер «Secure Chat» (FastAPI, SQLite, PyQt5, Bee2/криптографический стек, Node/Web-манифесты).
- **Разработанный инструмент**: `sastsca` — консольный анализатор статической безопасности исходного кода (SAST) и состава сторонних зависимостей (SCA).
- **Репозиторий**: `https://github.com/chelovek66/secure_chat.git`
- **Ветка разработки**: `feature/13-sast-sca-analyzer` (слита в `main`).

---

### 2. Реализованные методы и правила SAST

В анализаторе реализовано разделение на лексический (Regex) и синтаксический (AST) уровни:

| Правило | Уровень анализа | Критичность | CWE | Что выявляет |
| :--- | :--- | :--- | :--- | :--- |
| **SAST-001** (`Hardcoded Secret`) | Лексический (Regex) | High / Critical | CWE-798, CWE-312 | Поиск захардкоженных паролей, API-ключей, токенов и приватных ключей PEM (`BEGIN PRIVATE KEY`). Отсеивает безопасные плейсхолдеры (`changeme`, `admin`) и чтение из переменных окружения (`os.getenv`). |
| **SAST-002** (`Unsafe Function Call`) | **Синтаксический (AST)** / Regex | High | CWE-95, CWE-78 | Вызовы выполнения произвольного кода `eval()`, `exec()`, системных команд `os.system()`, `os.popen()` и небезопасного запуска процессов `subprocess.*(..., shell=True)` (Python) и `eval()` (JS). |
| **SAST-003** (`SQL Injection`) | **Синтаксический (AST)** | High | CWE-89 | Динамическая интерполяция строк в SQL-запросах (`cursor.execute()`): f-строки, оператор `%`, вызовы `.format()` и конкатенация `+`. Безопасными признаются параметризованные запросы с кортежами аргументов. |
| **SAST-004** (`Insecure Deserialization`) | **Синтаксический (AST)** | Critical | CWE-502 | Использование функций уязвимой десериализации `pickle.loads/load`, `yaml.load` без безопасного загрузчика `SafeLoader`, а также `marshal.loads`. |
| **SAST-005** (`Weak Cryptographic Primitive`) | **Синтаксический (AST)** / Regex | Medium | CWE-328, CWE-327 | Использование подверженных коллизиям и устаревших функций хэширования `hashlib.md5()`, `hashlib.sha1()` (Python) и `crypto.createHash('md5')` (JS). |

### 3. Модуль SCA (Анализ состава зависимостей)
- **Источники**: парсеры `requirements.txt` (экосистема PyPI) и `package.json` (экосистема npm).
- **Сверка с базой уязвимостей**:
  1. Онлайн-запросы к REST API **Google Open Source Vulnerabilities (OSV)**: `https://api.osv.dev/v1/query`.
  2. Локальный автономный кэш типовых уязвимостей (гарантирует функционирование в изолированных стендах).
- **Выходные параметры**: имя пакета, используемая версия, идентификатор CVE/GHSA, уровень критичности CVSS, рекомендуемая минимальная безопасная версия для обновления.

---

### 4. Управление ложными срабатываниями (False Positives) и ограничения
- **Фильтрация путей**: модуль `walker.py` считывает `.gitignore` и шаблоны исключений из `.sastsca.yml` (пропуск `tests/`, `venv/`, `__pycache__/`, `dist/`).
- **Специальные комментарии подавления**:
  - Python: `# nosec`, `# sast-ignore`, `# noqa`
  - JavaScript: `// sast-ignore`, `/* sast-ignore */`
- **Ограничения**:
  - Текущая версия фокусируется на лексическом и синтаксическом (AST) анализе внутри одного файла без полного межпроцедурного Taint-трекинга (межмодульного отслеживания потока данных).
  - SCA сверяет декларированные прямые зависимости; транзитивные зависимости определяются при наличии lock-файла.

---

### 5. Коды возврата CLI (Exit Codes)
- `0`: Находок с критичностью выше порога не обнаружено (сканирование успешно).
- `1`: Обнаружены уязвимости с уровнем критичности `>= fail_on` (сигнал блокировки сборки в CI/CD).
- `2`: Ошибка выполнения (некорректный путь, ошибка парсинга конфигурации).
